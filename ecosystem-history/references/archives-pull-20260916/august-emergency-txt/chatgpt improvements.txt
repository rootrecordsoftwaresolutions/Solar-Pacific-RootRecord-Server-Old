# Ava Improvement Guide

## Building a Persistent AI Developer & Community Assistant

---

# Vision

Ava is not just a chatbot.

She is the persistent AI developer, project manager, community assistant, and knowledge system for the RootMC ecosystem.

Her goals are to:

* Assist the community.
* Help develop RootMC.
* Learn from project history.
* Improve project code and documentation.
* Maintain a consistent personality across every platform.
* Never lose project context.

---

# Core Principles

## One Brain

There should only be one Ava.

Discord, Telegram, CLI, web dashboard, and future interfaces should all communicate with the same backend.

```
Discord
Telegram
Web Dashboard
CLI

        │
        ▼

      Ava Core

        │

Root Server
```

A user should be able to start a conversation on Telegram and continue it later on Discord without creating a separate personality.

---

## Personality vs Capabilities

Keep these separate.

### Personality

Responsible for:

* tone
* humor
* memory usage
* conversation style
* community interaction
* project identity

---

### Capabilities

Responsible for:

* Git
* Discord
* Telegram
* RootMC
* databases
* Linux
* documentation
* searching
* scheduling

Capabilities should be modular plugins.

---

# Memory System

Memory should be organized rather than storing everything.

## User Memory

Store information such as:

* preferred nickname
* timezone
* permissions
* previous discussions
* development interests
* moderation history (if applicable)

---

## Project Memory

Store:

* proposals
* decisions
* completed features
* rejected ideas
* bugs
* changelogs
* server rules
* economy information

---

## Knowledge Memory

Store:

* APIs
* documentation
* code references
* configuration
* Minecraft mechanics
* plugins
* server architecture

---

## Temporary Memory

Conversation-specific context.

Automatically expires.

---

## Development Memory

Store:

* bugs discovered
* code reviews
* TODOs
* benchmarks
* profiling
* design notes

# Plugin Architecture

Every capability becomes a plugin.

```
plugins/

discord/
telegram/
rootmc/
github/
git/
scheduler/
memory/
notes/
economy/
moderation/
documentation/
analytics/
voice/
```

Plugins expose functions rather than raw commands.

Example:

```
memory.save()

memory.search()

github.create_issue()

github.create_branch()

rootmc.lookup_player()

discord.send()

telegram.reply()

scheduler.create()

notes.record()
```

Ava should improve continuously without independently changing her own deployment.

The improvement loop should focus on:

* better documentation
* better prompts
* cleaner code
* more tests
* better tools
* improved memory organization

Changes remain reviewable and version-controlled.

2. Search memory.
